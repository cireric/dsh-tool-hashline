# 08: 全规格验收可从干净环境重复执行

**What to build:** 实施者能按规格命令，从构建到干净 profile 重复证明本期能力，并将每条需求追溯到实际用例和证据。安装、使用与已知限制文档反映最终行为，不依赖人工冒烟判断完成。

**Blocked by:** 04 — 连续编辑与有限守卫边界可回归；05 — read 提示与卡片在回放后仍可用；07 — 真正 PTC 下编辑与意图门契约成立。

**Status:** ready-for-agent

**Spec:** [权威规格入口](../spec.md)；§8.1、M4、NFR-3/5/6；其他票为本票传递前置，不另重复列阻塞边。

- [ ] 按实际用例补齐 FR-1 至 FR-14、NFR-1 至 NFR-6、§4 安装契约的追溯；记录用例 ID、命令和判定，不以检查组名称替代具体覆盖证据。
- [ ] build、既有递归 check/test，以及 test:unit、test:integration、test:ptc、check:preset、test:profile、test:compat 均可执行；每个失败以非零退出和可见原因报告。
- [ ] 编排使用前序票已交付的测试，不把全量测试留到本票才写，也不添加仅镜像实现的冗余测试。
- [ ] 在干净临时 profile 重复构建、依赖解析、bundles 登记、安装、真实重挂载、唯一 preset 发现和真实 PTC 编辑；原 ptc-roles 项目不可用时仍通过。
- [ ] 最终组合的 read 投影、窗口限制、无 tag 指引和编辑结果一致；真实普通、截断、空窗口、降级结果与卡片/回放检查共同覆盖。
- [ ] 正常未见锚点拒绝、错误回显重试、跨 session/淘汰/recovery/REM/block/mismatch 等有限守卫边界均有明确断言，不能把已知放行算成严格保护通过。
- [ ] 对平台或权限导致的未执行用例明确列缺项；必要验收缺项不能计为通过。符号链接等平台能力限制与执行证据一致。
- [ ] 安装和使用文档写明构建/激活/重挂载、全文读取成本、长行配置补救、无 tag 降级、seen 与 observed 的区别及有限保护范围；清除活跃入口中的历史 stub 指引。
- [ ] 升级流程指向可执行 compat gate；本期仍 private，不发布 npm、不接入日常 profile。只有证据满足规格判定后才把实施标为完成。
