# 文档维护与临时材料清理

## 信息归属

- 根 `AGENTS.md`：任务必读路由、实现边界、验收判据；项目介绍与阶段进度放 README 和验收索引。
- 根 `README.md`：项目用途、安装、使用边界、开发命令与文档入口。
- `docs/README.md`：文档职责、主题入口与阅读关系；当前状态统一指向验收索引。
- `docs/specs/` 定义需求，`docs/adr/` 记录决策，`docs/plans/` 解释实现与验证安排。需求变化先修规格；计划不能自行扩大需求。
- `docs/acceptance/` 保存各轮执行结果和机器摘要；当前状态索引维护最新结论及未覆盖范围。`docs/background/` 保存版本化研究，`docs/evidence/` 保存正式引用的证据。
- `.scratch/` 保存本地票据、草稿和原始证据；`.tmp/` 保存临时夹具或演练。两者都被 Git 忽略，目录名本身不构成删除依据。

## 修订与合并

现行规格、计划的状态说明随交付更新，链接到对应验收；正文中的实施前调查明确其时点。当前索引按主题维护，旧失败与修复报告以引用串联，避免不断叠加互相冲突的“当前”说明。

历史验收保留执行时的 PASS / FAIL / GAP / BLOCKED、环境和计数；可修链接、标题笔误或增加后续状态提示，不回写历史结果。研究建议不因整理文档而获得实施或升级授权。

相同信息只维护一份正文。合并前检查入链、原始证据与未决事项，更新引用；不同执行轮次的报告不能因主题相同而合并成一次结果。保留已有稳定路径，避免为目录整齐而制造迁移；失效路径修到实际权威文件。

## 删除依据

可清理：已完成用途的一次性提交说明；内容已完整进入正式文档、无独有证据且无保留引用的摘要或草稿。记录具体路径、理由、承接文档与删除前 SHA-256，清单放本轮 `.scratch/`，清理后复查引用。

保留：开放票据、未完成评测、失败对照、原始日志/会话、安装与输入哈希、回退备份，以及被报告引用的夹具和候选树。已关闭不等于失去参考价值。材料缺失或价值不确定时登记待查，不将它当作已审阅或无价值材料。

只做文档变更时，核对本地链接、来源与 diff，并运行 `git diff --check`；无需构建运行中宿主链接的源码树。涉及依赖、preset 或运行契约时按根 README 执行相应完整门禁。
