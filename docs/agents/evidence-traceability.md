# 证据可追溯（Evidence Traceability）

本文件是 [AGENTS.md](../../AGENTS.md)「验证与交付」的细则：那里约束**测试结果**的证据边界，这里把它扩到**结论**层。适用范围是所有交付物——调查报告、验收记录、评审意见、给用户的答复。

## 1. 不变量

每条写进交付的结论，必须能指回它的产出点，三类之一：

1. **已有证据**：仓库里已存在的文档、票据、验收记录；
2. **产生点**：产生该现象的代码、数据或配置，而不是描述该现象的那句话本身；
3. **责任层**：配置面（preset / 注册项）、实现面（依赖源码、本仓库代码）、数据面（输入与文件内容）。三者的修复手段与责任方不同，不能互相替代。

指不回产出点的，登记为待查项（GAP），不要写成结论。

## 2. 三个检查点

| 时点 | 检查 | 不满足时的典型症状 |
|---|---|---|
| 动手前 | 查 `docs/background/`、`docs/acceptance/`、`tests/compat/`、`.scratch/` 里的同题既有材料；重做须在报告里写明与存量的差异 | 交付一份“新发现”，实为既有结论复述 |
| 读到异常 | 报错文案列举的原因不是证据；先 grep 该文案的生产者，再采信任一条 | 把 “unsupported language” 当根因，实际是移植桩返回 null |
| 下结论前 | 先确定责任层，再回答“为什么” | 用“配置没开”的语言描述“本构建没实现” |

## 3. 准入测试：一条规则要不要进 AGENTS.md

三条同时满足才够格，否则留在本文件或 `.scratch/`：

| 判据 | 含义 |
|---|---|
| 跨任务恒定 | 对每类任务都生效，不是某类任务的步骤 |
| 有本仓库可指认的失败后果 | 能说出它挡住的具体事故，而不是“要更仔细” |
| 可从交付物上检出 | 别人看交付物能判断是否被违反 |

另外，[AGENTS.md](../../AGENTS.md) 只承载三类内容：任务→必读材料的路由、不可逾越的边界、验收判据。**执行顺序**（先做什么、再做什么）不进 AGENTS.md。

## 4. 反例（2026-10-25，一次真实交付）

- 用户要求验证 Hashline 编辑能力。整轮没有查 `docs/` 与 `.scratch/` 的同题存量，交付了 5000 字报告，其中块定位器的结论与三处既有材料重复：[10-23 能力分析](../background/2026-10-23-dsh-hashline-feature-analysis.md)、[兼容矩阵说明](../../tests/compat/README.md)、`.scratch/hashline-block-locators/issues/01-03`。第一轮工具调用的输出里已出现 `.scratch/hashline-default-editing/effectiveness/…`，被当成噪声滤掉。
- 同一报告把 `PUT N*` 的报错文案（“unsupported language / parse error”）当根因落盘，实际是 `dist/hashline/block-resolver.js` 的三行移植桩 `() => null`；并把“块替换/剪切不可用”扩大成“所有 `N*` 抛错”——`PUT >N*:` 实测是降级为普通插入并附警告。
- 两处都不是推理深度问题：查存量、grep 一次报错文案，各是一次工具调用。

## 5. 与其他规则的关系

- AGENTS.md「验证与交付」的 PASS / FAIL / GAP / BLOCKED 管**结果状态**；本文件管**因果解释与新颖性声明**。
- 与[领域文档约定](domain.md)的“用 GLOSSARY 词汇”“与既定 ADR 冲突要显式标注”同源：都是让结论可核对，而不是让措辞更自信。
