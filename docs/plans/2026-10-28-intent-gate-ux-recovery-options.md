## 问题一句话

声明失配后我们**已经把工作救回来了**（扣下旧正文、声明专用修复、同请求续步），但被扣下的那一次仍以 `turn/end: error` 结束，所以用户在声明出现之前会看到一次「本次请求失败 / This turn failed」原样提示。产品要求 IG-B-05/20 想要的是「恢复中」。

## 路线 1：Client 面呈现插件（保留要求）

**做法**：在本 bundle 里新增一个 Client 面模块（经 Plugin Manager 已安装 Client 模块的公开入口装载，而不是改宿主），把**特定失败码**（`INTENT_DECLARATION_MISSING` / `_EMPTY`）的 turn 终点渲染成「正在补全意图声明」，并把随后那条真正的声明消息与业务回复串成同一次交互。底层记录保持不变：`assistant/attempt`、`turn/end: error`、原始失败码都还在日志里，只是不再用「失败」的语气呈现。

| 维度 | 说明 |
|---|---|
| 新增资产 | 一个 Client 模块（渲染映射 + 本地化文案），随 bundle 交付；**不新增宿主改动** |
| 受影响范围 | 仅 Web 客户端。**CLI/ACP 仍由宿主决定**：`packages/acp/acp/src/session.ts` 直接以 `turn failed: …` 拒绝，本仓库改不到 |
| 需要的新证据 | 真实浏览器穿透（现有 `test:surface-gate` 只证明控制器帧，不证明页面）：同一会话的屏幕/帧序列里**没有** `message.turnError`，且声明与业务回复可见；取消时不出现「恢复中」残留 |
| 风险 | 两套呈现规则（Web 改造、CLI 不改）会不一致，必须在文档里说清；用户可能仍从 CLI 看到失败 |
| 与计划的关系 | 满足 IG-B-05/20 的字面要求；需要新增「Client 面呈现」这一层验收，并把 FIX-08 的判定扩到浏览器 |

## 路线 2：改写要求，接受一次可见暂停（最小改动）

**做法**：把 IG-B-05、IG-B-20 与 IGB-AC-18 改成「首次失配可以呈现为**一次策略暂停**（措辞清楚说明『正在补全声明』），随后同一请求自动续步；不得发布旧正文、不得执行旧调用、不得要求用户重发」。FIX-08 的判据随之改为「无旧正文泄漏、旧调用零执行、业务无需用户重发、用户不被迫重述目标」，不再要求「界面上不出现失败字样」。

| 维度 | 说明 |
|---|---|
| 新增资产 | 无（只改规格/验收/文案评审） |
| 受影响范围 | 产品要求本身；所有呈现端一致（Web/CLI 都能看到一个明确的暂停，而不是自相矛盾的两种状态） |
| 需要的新证据 | 重跑 P5 的宿主 + 呈现端门禁，记录这次可见暂停，并在验收里写明它是**被接受的**行为 |
| 风险 | 用户仍会看到一次「失败/暂停」；文案必须避免让人以为任务没做 |
| 与计划的关系 | 计划允许「明确承认底层 turn 边界，不在日志造假」，但要求把决定写进 ADR 与规格，不能默默接受 |

## 路线 3：向上游要一个官方 seam（不改本体，但要等）

**做法**：向上游提出提案：允许 `agent/request-error` 的返回把本次尝试「挂起」而不是终结 turn（或提供一个「attempt withheld」的官方状态），使同 turn 换 step 成为官方能力。我们这边只写提案与最小复现，不改宿主。

| 维度 | 说明 |
|---|---|
| 新增资产 | 提案文档 + 最小复现脚本；**无实现** |
| 受影响范围 | 依赖上游排期；在此之前 P3 仍是 BLOCKED |
| 需要的新证据 | 上游接口的真实存在性（同 ADR-0006 修订 §1 的路线 A 证据，再补官方文档/类型） |
| 风险 | 时间不可控；不能因此停掉其它分支（目前已停的只有这一条） |

**已选定：路线 1**（用户 2026-10-28 决定）。呈现规则核心已实现并有测试；浏览器半因缺宿主 client 依赖与构建环境仍 BLOCKED，进度与接线步骤见[设计稿](2026-10-28-p3-route1-client-presentation-design.md) §3b/§7。路线 2 的精确改动面仍留在该文附录，作为路线 1 落地失败时的备选。

## 建议（供评审，不是决定）

先选 **路线 2**（立刻可交付、端到端一致、零新资产），同时把 **路线 3** 的提案作为长期改进；只有当用户明确希望「Web 端完全不出现失败字样」时才做**路线 1**，并且必须同时接受「CLI 仍会显示失败」的说明。

## 选定之后要做的具体改动（预告）

- 路线 1：新增 Client 模块 + 浏览器穿透用例 + FIX-08/IGB-AC-18 扩写 + 交付包清单与 `check:preset` 资产摘要。
- 路线 2：改 IG-B-05/20、IGB-AC-18、FIX-08 判据 + ADR-0006 补一条决定 + 重跑 P5 记录该可见暂停。
- 路线 3：写提案与复现，不改代码；P3 保持 BLOCKED。
