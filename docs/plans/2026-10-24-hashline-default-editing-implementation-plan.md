# PTC Hashline 默认编辑策略实施计划

- 日期：2026-10-24；版本：r1。
- 权威需求：[默认编辑策略 SRS 1.1](../specs/2026-10-24-hashline-default-editing.md)。本文解释实施方案，不另立需求正文。
- 状态说明（2026-10-25）：票据 01～08 的[工程切片已交付](../acceptance/2026-10-24-default-edit-policy-engineering.md)，后续 [fix-01](../acceptance/2026-10-25-default-edit-policy-fix-01.md) 与 [fix-02](../acceptance/2026-10-25-default-edit-policy-fix-02.md)已复验；完整 E2、E3 与 E4 尚未完成。正文设计事实按实施前时点阅读，当前缺口见[状态索引](../acceptance/2026-10-23-current-status-and-evidence-index.md)。
- 授权边界：计划与票据状态不自动授权安装、目标切换、宿主重启或发布。历史工程实现不代表真实模型或推广验收已通过。

## Problem Statement

PTC Hashline Mode 已有可用的 read→tag→edit 链路，但 auto 按参数选择分支，模型能够持续使用 replace。现有指令还存在固定模式、直接降级及无条件回退等冲突。用户需要默认采用 Hashline、让受管 edit 拒绝不合格替代更新，并能区分工具接受、业务正确和实际收益。

本计划以 SRS 的 FR-01～07、NFR-01～06、POLICY-01～21、VALUE-01～02 为完成依据。基础读写、有限 seen、目录、BOM、MV 与 CAS 仍遵循[基础规格](../specs/2026-10-22-ptc-hashline-requirements-spec.md)、[术语表](../../GLOSSARY.md)及相关 ADR。

## Solution

保留一个上游 edit 实现与 auto 分流，通过现有精确补丁增加可选策略接入点，仅由目标 preset 配置启用。随 bundle 交付一个策略模块，集中处理操作分类、降级核验、读取事实、用户来源和最小回执。read 只提供可信读取事实和目标 preset 的指引文案，不加载策略模块、不增加运行时依赖。

首版的主测试 seam 是真实 ToolRuntime 的 scoped edit / run_code 调用到真实 Local filesystem 的结果。测试通过同一入口观察拒绝、原工具输出与磁盘变化；执行期间的竞争由现有 provider 写入观察 seam 注入。装配、实际子代理和模型纪律在更外层验证，不用内部函数的返回值替代这些证明。

### 静态核对的当前事实

以下来自本轮对安装产物与仓库的只读检查；不是新策略运行结果。

| 当前事实 | 实施含义 |
|---|---|
| edit 版本锚点仅重导出上游插件；auto 优先识别 old_string、再识别 edits，最后判断 input | 保持锚点薄；在真正分流前检查三类载荷互斥，不能仅审查 input 文本 |
| replace 在同一次 execute 内遇 stale-version 最多重跑一次 | tools/pre-execute 的一次检查不够；策略必须进入编辑器本次调用与重试的生命周期 |
| patch/apply_patch 当前逐项执行；patch 有无写入的 preview 能力 | 复用原解析和 preview 做策略预检，不复制匹配算法；预检通过不代表提交事务 |
| 上游执行上下文会精简 agent，丢失完整调用关联字段 | 策略在精简前捕获真实 ToolRunContext，并通过调用私有对象传递；不用全局“当前调用”变量关联证据 |
| read 内部知道实际 caps、归一化字节数及完整行，canonical value 无这些全部信息 | 不能把解析 nextAction 文案当事实；新增内部只读事实通知，保持 canonical schema 不变 |
| 归一化 UTF-8 字节数达到 snapshotMaxBytes 即不 mint；零字节与单 BOM 空文件均不 mint | 按真实门槛核验；空文件分类与字节保真分别处理 |
| 已有 scoped policy、CAS 竞争、PTC carrier 和真实 registry/loader 夹具 | 优先扩展已有 seam；其他 preset 和现有无策略模式作为对照 |
| 本 checkout 当前没有可解析的真实 tool-subagent 包；已有 skill 装配夹具只装 skill 行 | 最终委派和完整 preset 验收须从真实宿主安装组合取得；当前夹具不能替代 |

## User Stories

1. 作为主代理使用者，我希望普通局部修改默认走 Hashline，以便利用已有 tag 和行号定位。（FR-01）
2. 作为使用者，我希望重复片段只修改指定位置，以便避免业务内容误改。（FR-01/05）
3. 作为使用者，我希望按需补读及连续编辑使用真实新依据，以便不混用新 tag 与旧行号。（FR-02）
4. 作为使用者，我希望无关行截断不影响完整目标的 Hashline 编辑，以便避免不必要降级。（FR-02/03）
5. 作为使用者，我希望真实超限目标在依据充分时可以使用替代模式，以便仍能完成任务。（FR-03）
6. 作为使用者，我希望长行经获准渠道取得完整原文后仍可按窗口限制降级，以便例外条件与内容充分条件同时成立。（FR-03）
7. 作为使用者，我希望明确覆盖默认的请求有可追溯来源及范围，以便模型不能虚构授权。（FR-03）
8. 作为委派任务的使用者，我希望子代理可引用合法父会话用户来源，同时建立自己的文件依据，以便来源追溯不变成快照共享。（FR-02/03/07）
9. 作为使用者，我希望真正创建与空文件填充可正常使用已有能力，以便初始内容不需要伪造 tag。（FR-01）
10. 作为使用者，我希望单 BOM 空文件填充保持任务要求的字节特性，以便创建类例外不掩盖保真损失。（FR-01/03）
11. 作为使用者，我希望纯删除或移动沿用原契约，而移动并修改内容仍受策略约束，以便目录和不覆盖保证保持有效。（FR-01/06）
12. 作为使用者，我希望混合请求中一个合法例外不能放行其他普通更新，以便整次 edit 在写前完成策略核验。（FR-06）
13. 作为使用者，我希望文件、目录或配置变化后重核验，以便旧依据不能支持新的执行或内部重试。（FR-06）
14. 作为使用者，我希望冲突、取消及部分成功后先核验现场，以便避免盲目重放或撤销已有工作。（FR-04/05）
15. 作为使用者，我希望目标已满足时结束、同目标三次失败后停止，以便控制无效恢复成本。（FR-04）
16. 作为其他 preset 的使用者，我希望工具行为保持原样，以便目标策略不会泄漏到并行会话。（FR-06/07）
17. 作为维护者，我希望实际 prompt、SDK 与 nextAction 一致且仍输出原 string/header，以便指令和程序消费都可靠。（FR-07）
18. 作为维护者，我希望记录调用方式、核验和部分结果但不额外复制正文，以便能审查偏离与 unknown 而不扩散敏感数据。（FR-07）
19. 作为维护者，我希望补丁可打包安装并核验真实解析路径，以便同版本号不会掩盖补丁未加载。（NFR-01/02/05）
20. 作为推广决策者，我希望独立报告真实模型正确性、返工和总成本，以便采用率提高不会被当作净收益。（NFR-03/06、VALUE-01/02）

## Implementation Decisions

### D1. 模块与接入方式

只增加一个 bundle 内的默认编辑策略模块；内部纯判定可按实际复杂度拆分，不新建策略服务、全局 registry 或通用写入代理。

| 模块 | 改动职责 | 保持的接口 |
|---|---|---|
| 上游 edit 精确补丁 | 增加可选策略模块配置、fallbacks 输入、调用私有生命周期、批次预检和内部重试重核验；沿原工具返回结果 | edit 名称、auto 真实分流、输出 string、原有解析/匹配/recovery/no-op 及 FS 条件写入 |
| bundle 策略模块 | 读取事实索引、原因与范围核验、用户来源、操作分类、最小记录；每次注册创建独立实例 | 不注册第二个 edit，不替代宿主 permission/approval/observed 判定 |
| 自有 read | 可选内部事实通知、目标 preset 指引文案；事实在成功工具结果后才可使用 | 原参数和 canonical schema、窗口、mint/seen、有效目录、运行时依赖白名单 |
| preset 与 persona | 配置可选模块和指引开关；独立策略 prompt 段；局部协调失败恢复；更新允许的资源基线 | watchdog 正文、Intent 判据、其他 preset、运维 skills 工作流 |
| 验收与评测驱动 | 扩展已有测试、打包后运行检查和脱敏结果导出 | 原门禁入口和历史记录；工程与推广结果分别交付 |

编辑器配置新增可选 contentPolicyModule，由 preset 用现有安装资源根解析惯例提供模块地址。缺省时不增加 fallbacks 字段、不启用互斥新规则、不加载模块、不增加策略 I/O，保持其他 preset 的原行为。锚点包仍仅重导出上游；接口声明与精确补丁、锁文件同步交付。

模块提供 createPolicy 工厂；编辑器在本次注册的 context 中初始化，得到 preflight、beforeMutation、settle 三个阶段的接口及 dispose。它们分别处理完整调用、当前目标即将产生的副作用、已知结果；内部状态归本次挂载与 Session 对象，不使用进程全局可解锁状态。预检返回的对象只在本次调用内流转，不暴露成模型可复用的许可。

模块加载失败或核验接口异常时保留明确的不可用状态，受管非 Hashline 请求拒绝。基础会话上下文检查仍执行；能正常执行的 Hashline 不因降级核验不可用而被一律禁用。只有未配置策略的注册才走原行为，不能把受管模块故障当作退出策略。

### D2. 输入契约与真实模式

保留现有参数及路径别名。受管注册新增可选 fallbacks 数组，每项精确绑定一个目标及一种原因；多目标和同文件多范围按项核验。正常 Hashline 不要求该字段。

| 字段 | 拟定接口及校验 |
|---|---|
| path | 目标作者路径；按现有有效 workingDirectory、show path 与 store key 规则解析，必须与实际更新目标匹配 |
| reason | 只允许 snapshot-limit、window-limit、user-override，分别对应 SRS 三类原因 |
| readCallId | 前两类原因必填；引用当前编辑会话成功 read 的真实调用，不是模型填写的 bytes/tag 自述 |
| ranges | window-limit 必填；若干 startLine/endLine 闭区间，使用该次 read 对应版本的行号，关联本次实际修改目标；无关截断行不能支持普通目标 |
| userSource | user-override 必填；sessionId、eventSeq、textBlock、start、end 引用原始用户文本片段，字符范围按 JS 字符串索引解释，不复制原文 |
| modes | user-override 必填；声明本次替代方式，值限定 replace、patch、apply_patch；实际分流必须在范围内 |

对象拒绝未声明字段，原因对应的必填、互斥字段和范围在工具实际执行中校验，并进入生成 SDK。使用宿主支持的 object、array、enum 和 oneOf 等 schema 形态；不引入宿主未支持的条件 schema。由模型传入的引用只用于定位，不能直接作为已核验事实。

在受管入口对 old_string/new_string/replace_all、edits、input 三组按字段存在检查，先拒绝跨组并存，再执行各组原必填和语义校验，再用原 dispatchMode 得到真实模式。路径别名仍采用原规则，不新增另一套别名规范化。

所有受约束更新都必须有匹配项，缺失、重复矛盾、不能关联或未被本次调用使用的降级声明返回明确参数/依据缺口，不生成“整个文件或会话已解锁”的状态。原因成立后仍交原工具判断匹配、语法和写入条件。

### D3. 读取事实与依据生命周期

read 通过已有 context 通知能力发布内部事实，包含真实 exec token/callId、Session、cwd、解析目标、show path/store keys、stat version、实际 caps、归一化字节数、空文本状态及返回窗口的完整/截断行事实。通知不携带全文、不改变 canonical value，也不让 read 运行时导入 bundle 模块或宿主实现。自定义通知必须显式核对本次注册的 scope/Session 归属，不能假定所有 context 事件自动隔离；并行会话即使出现相同 callId 也不能串用记录。

策略模块观察成功工具结果后提交记录；失败、取消、输出校验失败或最终被拒的 read 不成为有效依据。通知缺失或无法与成功结果关联时，报告缺口并要求有效读取，不从 nextAction、卡片后缀或另一会话日志猜造事实。

记录以 Session 对象为所有者、readCallId 为引用，保留 cwd、实际目标、version、caps 与窗口事实。索引只保存必要元数据，按宿主会话/挂载生命周期释放；每个目标仅保留足够验证当前状态的读取事实，淘汰引用后明确要求重建，不变成长期正文缓存或常驻遥测。

每次 edit 根据当前 cwd 重新解析，核对实际目标、文件状态、有效配置与引用事实。没有变化且版本能确认一致时复用；版本或身份变化则旧记录失效。文件版本没有足够可信度、或读取期间一致性无法确认时，使用有前后 stat 的当前文本核验；不能确认则拒绝相应替代更新。tag 不是这里的唯一版本凭证。

基于原始 stat 的读取事实只有在后续核验能确认其内容、身份和版本一致时才能支持降级；不把“read 曾成功”当成永久有效。后续执行与内部 retry 都走相同核验函数，保留原 writer 的条件写入/CAS，接受基础 provider 已有的并发能力边界，不宣称获得文件锁。

### D4. 三类原因的客观检查

| 原因 | 执行层核验 | 留给模型与业务验收的判断 |
|---|---|---|
| snapshot-limit | 当前会话有效 read、真实归一化 UTF-8 bytes ≥ 当时且当前生效的门槛、目标和版本对应 | 已取得足够理解及唯一定位的原文，修改符合任务 |
| window-limit | ranges 对应真实受列/字节限的目标；offset/limit 分页不能补足；实际更新范围与声明相关；完整普通目标不能借无关截断放行 | 修改所需上下文是否足够，获准替代原文是否被正确理解 |
| user-override | 真实 Session 中存在引用事件和片段，来源明确为 user；会话/委派关系、目标及实际模式在声明范围内 | 原文是否确实要求该方式与范围；系统不宣称自动证明自然语言意图 |

窗口限制与替代内容充分分别核验。获准渠道取得完整长行不撤销 canonical read 的列限事实；同配置可正常补读的遗漏先补读。编辑器自身的执行准备读取不冒充模型此前成功 read，但可用于核对实际文件状态、模式适用性及声明范围。

用户来源先查当前活 Session；父来源仅沿真实 parentSession 与受托关系追溯，同时核对宿主委派记录和本任务关联。仅有 fork 血缘、模型转述或相同用户文本都不足以证明合法委派。优先使用宿主 Session 查询接口；父会话不在内存时，通过宿主已有只读会话查询/持久化能力取证，接口不可用或范围不明就拒绝该降级，不扫描其他会话碰运气，不增设审批框架。

历史恢复可重查真实用户事件；文件窗口事实必须属于当前编辑会话并重新核验。若新运行实例没有可核查的读取事实，则重新 read 建立引用，不回写旧历史或把父会话快照复制给子代理。

### D5. 操作分类、整次预检与内部重试

所有步骤均属于单次 tools.edit，不扩展到整个 run_code。

1. 在原执行上下文精简前捕获 Session、callId/rootCallId、signal、scope 与本次有效 cwd。受管调用必要上下文缺失即拒绝。
2. 校验载荷和 fallbacks，执行真实分流。复用上游 apply_patch 展开、patch 条目及 Hashline 解析/prepare，不用正则猜输入是否“看起来是 Hashline”。
3. 对完整请求解析所有目标与移动两端，取得初始状态；以实际存在性、归一化空内容及操作整体效果分类。Hashline 沿原路径校验，不另收紧 seen/recovery；非 Hashline 更新执行降级核验。
4. 对依赖前序结果的非 Hashline 条目，复用上游 preview/dryRun 与请求内短寿命文件视图得到候选 before/after，按原顺序更新视图。它只模拟本次请求已解析的目标、存在性与文本，不成为新的 provider、持久快照或权限系统；不复制解析/匹配算法。由实际 before/after 判断纯移动与内容更新，并识别删除后重建、移动后再覆盖等组合。
5. 首次磁盘写入前核验全部受约束目标；任何策略项不合格则不开始本次写入。预检不调用真实 writer、mkdir、delete 或 move；读取与原有 seen/observed 变化不被误报为磁盘写入。
6. 放行后仍走原执行器和原顺序，不提交预检缓存去替代执行器的当前读取。beforeMutation 在副作用前复核身份、版本、配置及许可范围；本次成功写入可以更新请求内预期状态，外部变化使相应依据失效。预检与实际准备结果分歧须重新核验，不能沿用宽泛放行。
7. replace 的原有一次 stale-version retry 在同一调用对象内重建事实、重新 preflight；若原因不再成立，停止重试更新。patch/Hashline 不新增整批自动重试。
8. 逐条记录已知执行进度；后续拒绝、异常、取消均保留已落盘事实及 unknown，交原错误语义报告部分完成，不自动回滚或重放。

创建预判继续受原条件创建与并发冲突约束，不授权覆盖后来出现的文件。纯删除/移动保持原目录、目标不覆盖及部分完成契约；策略不为原工具补出新能力。有关 MV 的源删除版本限制保持 [ADR-0004](../adr/0004-mv-create-intent-and-snapshot-order.md) 的已知边界。

零字节与单 BOM 空文件可归创建类例外；仅含空白、连续 BOM 不获例外。分类检查需要时只探原始前缀，并结合真实解码结果及版本确认，避免双重 strip 把连续 BOM 当空。单 BOM 填充在候选内容与实际写入路径能满足任务保真时放行，否则明确停止；不凭新分类宣布所有替代模式都保 BOM，不改变 [ADR-0005](../adr/0005-bom-preserving-hashline-read.md) 的支持范围。

### D6. prompt、nextAction 与最小记录

独立注册默认编辑策略 prompt 段，避免使用 deployment persona 的同名段；同 preset 子代理覆盖 persona 后该段仍需可见。局部改写 persona 的无条件 REVERT，协调 edit 描述、参数说明与 tool:edit 的 auto 文案，不修改 watchdog 或 Intent 判据。

read 新增缺省关闭的策略指引配置，只由目标 preset 启用。它只调整 nextAction 文案及相应渲染，不改原返回字段、nullable schema、caps 或 mint 条件。无 session 指向上下文缺口，真实超限指向受控降级条件，长行不引导擅自调配置或重挂载。其他 preset 保持原指引。

优先复用调用日志和 string 回执。成功 edit 的原 string/header 保持可解析；需要补充时只追加简短策略回执，不在 header 内插入字段。拒绝或失败沿原错误通道提供稳定的策略错误类别及具体缺口，不借 no-op 文案被转换成成功。策略错误不伪装为宿主 FsError，不吞掉已有宿主错误。

最小回执包含策略版本、调用关联、声明/解析目标、载荷类别、实际分流或未执行、原因及依据引用、核验结论、已完成/未变更/失败/部分完成/unknown。系统核验与模型语义判断分开记录。PTC 用原 string 读取回执；不能把 meta 写入说成 SDK 获得新结构化字段。可观察到内部 retry 时记录其序号，但仍算同一次工具调用。

未派发的宿主拒绝从原日志识别，不能伪造策略核验已执行。导出按 callId/rootCallId/subCallId 配对，start/settle 不重复计数；只输出必要引用、摘要与缺口，不新增原始用户片段、文件正文或环境快照。不新增 Session 事件类型或借不受支持的插件记录接口改写宿主日志协议。

### D7. 新增 I/O 与代价控制

| 场景 | 新增操作及复用策略 |
|---|---|
| 未配置策略的其他 preset | 不加载策略、不做策略 stat/read；read 原指引保持原样 |
| 普通受管 Hashline | 事实通知为内存元数据；继续复用原 read/prepare，不额外逐笔全文读取；回执与 scope 检查计入成本 |
| 降级预检 | 每个唯一目标至少一次当前 resolve/stat；需要空文件、超限或候选效果确认时读取文本，必要时做前后 stat；同一请求复用已验证读取 |
| 窗口限制 | 优先使用成功 read 的真实窗口事实；版本不能确认时重新读取核对，不能靠重复相同窗口探索剩余列 |
| BOM 例外 | 需要时增加最多六字节前缀读取及一致性 stat；只对相关目标执行，不为所有编辑读全文字节 |
| 批次与提交前复核 | 请求内候选视图保留必要文本，执行后立即释放；beforeMutation 以 resolve/stat 和仍有效的已核验事实为主，失效才重新读取 |
| 用户覆盖 | 优先内存事件及宿主已载入 Session；需要持久化查询时单列查询/解码次数，不每次扫描整个会话目录 |
| 内部 retry | 重核验可能增加 stat/read；单独记录，不误计为额外模型请求 |

预检后仍保留上游实际准备读取，因此部分批次会增加全文读取和内存占用；不宣称大文件有界内存或必然省 token。实施用 I/O 观察记录实际次数，区分首次读取、按需补读、策略核验和失败返工；评测计总成本，未知指标保留 unknown。

### D8. 实施顺序与完成条件

这些是拆票依据，不是本轮已发布的实现 tickets；后续按可验证的完整行为切片，避免只拆 schema 层、逻辑层和测试层。

| 阶段 | 交付的完整行为 | 完成条件与依赖 |
|---|---|---|
| M1 | 目标注册识别、正常 Hashline 与未声明普通 replace 拒绝；其他注册保持原样 | 真实 ToolRuntime 正/负向和不受影响对照通过；先完成，建立模块、schema、回执与 SDK 的最小闭环 |
| M2 | read 事实到 snapshot/window 两类降级 | 真实受限成功、虚构/无关截断/失效/跨会话拒绝；缺失内容停止；依赖 M1 |
| M3 | 用户覆盖及合法子代理来源追溯 | 来源真实、范围和方式相符才放行；父来源不共享 read/seen；依赖 M1，复用 M2 的事实生命周期 |
| M4 | 空文件/BOM、混合请求、请求内依赖、目录变化与内部 retry | 写前拒绝无本次写入，放行后部分完成如实报告；依赖 M2/M3，保留全部旧契约对照 |
| M5 | 实际指令、SDK、完整装配、打包后执行及回归 | 资源摘要、运行解析路径、真实子代理与 PTC 证据齐备；依赖 M4，不以 dump-config 独自判定通过 |
| M6 | 冻结真实模型评测方案并执行对照 | 采用/正确/返工/成本、异常样本与 unknown 完整报告；依赖 M5 的工程结果及评测前冻结，不借本计划预定收益 |

## Testing Decisions

### T1. 提交用户确认的测试 seams

主 seam 只有一个：真实 ToolRuntime 的 scoped 调用到真实 Local filesystem。新增策略大多数行为都在此验证，使用真实 read、上游 edit、fs-observation-policy、workingDirectory 与原结果校验；调用者和测试穿过同一接口。

在这个主 seam 上复用已有 provider 写入观察 seam，记录 intent、磁盘和竞争时序；它只属于测试，不占用 fs/*-intent 决策槽位。不要为每个内部判定函数另建一套 mock 测试；少量纯输入/范围计算只在主 seam 无法直接定位边界时补单测。

PTC 测试仍走真实 SDK/bridge，允许使用已有进程内 carrier，但明确它不证明实际执行后端隔离。最终增加真实 launcher、完整目标 preset 和实际委派工具的外层验收，读取实际组合 prompt/SDK/nextAction，观察 persona 覆盖后的子代理和非目标 preset。模型纪律与 VALUE 只由真实模型任务记录证明。

### T3. 既有测试先例与门禁

复用[scoped policy 与竞争夹具](../../tests/integration/edit-policy-harness.ts)、[两模式组合测试](../../tests/integration/edit-policy-composition.spec.ts)、[scope 拓扑测试](../../tests/integration/edit-policy-topology.spec.ts)、[PTC 错误传播](../../tests/ptc/edit-policy.spec.ts)、[persona scope 契约](../../tests/integration/persona-scope-contract.spec.ts)及[真实 registry/loader 夹具](../../tests/integration/operations-preset-harness.ts)。后者仅是装配机制先例，不能把其 skill 子集结果当成完整 preset 验收。

获准实施后逐个行为先建立红测，再让最小实现通过；常规开发只跑受影响测试和类型检查。依赖、preset 或运行契约变更完成后执行 README 的完整门禁：pnpm check、test:unit、test:integration、test:ptc、test:compat、check:preset、test:profile，并另跑 test:delivery。记录命令、退出码、skipped、环境和补丁真实解析路径。

扩展真实交付驱动，打包安装后从安装资源根加载模块，并实际调用受管 edit；完整装配必须验证真实路由与副作用，不能只检查模块存在、配置字符串或版本号。测试只能在隔离副本/一次性 profile 内更新依赖，不能热改当前宿主使用的链接树。

复用现有交付报告机制时新增本需求的报告归属，避免重跑覆盖同日运维交付历史；输出本功能独立报告并在当前验收入口新增引用。缺实际子代理、真实后端或模型凭据时分别记 GAP/BLOCKED，不能放松测试或用手造对象充当最终证明。

## Out of Scope

需求范围沿用 SRS §3.2。尤其不增加全写入拦截、永久解锁令牌、跨调用事务、运行时三次失败计数器、自动 old_string→Hashline 转换或统一自然语言授权判定。

不改 hashline 引擎算法、有限 seen、read/edit canonical schema、PTC 错误含义或 Intent 门；不借本计划重构运维工作流。原实现内部错误和补丁不足按实际证据处理，不为了策略另复制上游解析器。

不预定模型收益或推广结论；真实模型、参数、重复数、顺序、预算及正确性/成本通过条件在评测执行前单独冻结。工程通过但 VALUE 证据不足允许分别报告，不授权目标切换。

- 批次预检和原执行器可能产生重复读取；用 D7 实测成本，不以估算宣称收益。若 preview 无法保持某种条目的原语义，应先修复该接入设计，不能跳过该条策略核验或复制实现。

- 父会话查询和实际委派链的可用性必须通过真实宿主验证；缺少来源只影响该次覆盖降级，不能静默放宽或转用别人的文件事实。
