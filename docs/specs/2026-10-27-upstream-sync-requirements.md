# PTC 与上游能力同步需求规格

日期：2026-10-27

Status: ready-for-agent

需求来源：本轮 grill-with-docs 的 Q1～Q13 逐项确认，以及 to-spec 阶段对公开检查入口测试边界的确认。本文为需求权威正文；尚未实现、未验收，不构成依赖升级或目标切换授权。

## Problem Statement

维护者需要持续跟进本机 DSH 的 PTC Mode、上游 hashline/tool-edit，以及自有 tool-read 所参照的 stock read 能力。三者分别演进，单纯比较版本号不能回答工具、提示、调用契约和本地补丁是否仍然兼容。

现有受控升级流程已有基线、来源查询、候选验证及目标切换能力，但尚不能完整回答上述范围发生了什么变化、哪些差异有意保留、哪些需要跟进。维护者需要可重复运行、能保留依据的检查，避免依靠一次性人工盘点，也避免将来源失败或未验证误报为已同步。

## Solution

提供一个由维护者手动发起的公开同步检查入口，读取配置、采集来源身份、比较变化，生成本地可读报告与结构化记录。后续运行能够识别已知差异、新增变化和需要重新评审的旧决定。

上游同步意味着主动评估通用能力变化、按需适配并验证，允许保留有理由的 Hashline 差异。检查止于报告、建议和待办；维护者选定跟进项后，才转入适配及现有受控升级流程。

首版完成一次 Windows 真实来源完整检查，并验证重复运行及失败场景。首版不要求修复全部差距或完成一次实际升级。

## User Stories

1. 作为维护者，我希望手动发起一次同步检查，以便在决定是否跟进前取得依据。
2. 作为维护者，我希望检查本机指定 DSH 源码的当前内容，以便跟随自己维护的宿主版本。
3. 作为维护者，我希望用本次参数覆盖环境变量和本机配置，以便临时比较另一个来源。
4. 作为跨平台维护者，我希望各机器分别配置源码位置，以便无需修改项目模板。
5. 作为维护者，我希望使用自己维护的源码目录链接，以便切换本机目录时沿用检查配置。
6. 作为维护者，我希望缺少配置或链接不可用时得到明确原因，以便修正输入而不是依赖磁盘扫描猜测。
7. 作为维护者，我希望看到配置路径和实际解析目录，以便辨认本次到底检查了哪份源码。
8. 作为维护者，我希望允许检查含未提交改动的源码，以便分析本机实际内容。
9. 作为审阅者，我希望看到 commit、工作树状态和相关内容摘要，以便区分本地修改快照与上游发布。
10. 作为维护者，我希望比较 PTC 工具组成、配置及提示，以便发现遗漏和不兼容变化。
11. 作为维护者，我希望检查与本项目相关的 PTC 调用、委派和 SDK 契约，以便判断静态配置之外的影响。
12. 作为维护者，我希望保留独立 persona/watchdog 并检查兼容性，以便维护 Intent gate 的既有行为。
13. 作为维护者，我希望对照 stock read 的参数、返回值、截断、大文件和错误行为，以便确定自有 read 的跟进项。
14. 作为维护者，我希望发现两个引擎已发布的稳定版及预发布版，以便了解可选候选。
15. 作为维护者，我希望查看固定版本到候选版本之间的更新依据，以便判断是否值得跟进。
16. 作为维护者，我希望同时评估两个引擎的组合及补丁影响，以便避免分别升级造成不兼容。
17. 作为审阅者，我希望版本更新但行为依据不足时明确显示待查，以便避免把版本号当作安全结论。
18. 作为维护者，我希望每轮得到可读报告和结构化记录，以便审阅并支持重复比较。
19. 作为维护者，我希望区分新增变化和已知差异，以便集中处理新问题。
20. 作为维护者，我希望旧差异对应内容变化时重新提示评审，以便旧例外不会遮蔽新风险。
21. 作为审阅者，我希望保留差异和不适用结论附有理由、依据及复查条件，以便后续重新判断。
22. 作为维护者，我希望部分来源失败时继续独立检查，以便保留本轮仍能取得的结果。
23. 作为审阅者，我希望缓存和未知来源明确标记，以便不将历史信息误认为当前最新状态。
24. 作为维护者，我希望检查不修改源码、依赖或日常 profile，以便安全地反复执行。
25. 作为维护者，我希望选定跟进项后复用既有升级流程，以便保持候选验证和目标切换的授权边界。
26. 作为审阅者，我希望候选验证绑定检查时的输入，以便来源发生变化后重新检查。
27. 作为维护者，我希望看到真实来源、测试夹具和平台实跑的不同证明范围，以便判断结果是否适用于自己的环境。
28. 作为维护者，我希望未实跑平台明确保留 GAP，以便 Windows 交付进度和其他平台覆盖都如实呈现。

## Implementation Decisions

### 范围与入口

- 提供一个公开的手动检查入口，贯通配置、取证、比较和报告；具体命令命名在实现票据中确定。检查可在维护仓库使用，无需真实模型凭据。
- 复用现有运维基线采集、发布来源查询与证据处理能力；不足处补齐，不重建候选验证和目标切换流程，也不放宽现有运维 skill 的调用资格。
- 比较范围包括 PTC preset 工具组成、配置、提示，以及相关调用、委派和 SDK 契约；两个引擎的版本、行为与补丁；普通文本 stock read 的参数、返回值、截断、大文件和错误处理。
- PTC 和 stock read 必须来自同一个选定 DSH 来源。自有 tool-read 是对照适配对象，不是第三个待升级上游包。无关宿主模块不做全面审计。
- 静态差异只证明内容变化；行为影响须附分析或测试依据，无法确定时保留待分析。不得因文件相同、版本相同或补丁标记存在就声称全部语义兼容。

### 来源与身份

- DSH 路径选择顺序为：本次显式参数、DSH_CHECKOUT 环境变量、本机配置。未提供时报告缺少配置，不扫描磁盘。高优先级指定来源不可用时明确报告，不静默换用其他来源。
- 提交可复用配置模板；本机实际配置由版本控制忽略，不将当前用户的 Windows 路径硬编码为默认值。支持用户维护的链接，记录输入路径和实际解析目录，不创建或修改链接。
- “本机最新”指选定目录的当前内容，不宣称是网络最新发布，也不自动下载、拉取或升级 DSH。
- 记录本项目与 DSH 的版本声明、commit、工作树状态、相关文件摘要及取证时间。不能取得的身份字段明确为 unknown 并说明影响。允许本地修改快照，不能将其标为上游发布。
- 本项目基线区分精确依赖声明、锁定依赖、补丁身份与可取得的实际安装解析结果。无法取得安装证据不影响独立源码检查，但不得声称已验证实际加载或补丁语义。
- hashline/tool-edit 查询已发布版本，包含 alpha、beta、rc，分列稳定版和预发布候选；版本按语义版本规则比较。保留查询来源与时间，覆盖固定版本到候选版本的更新依据和二者组合兼容性。
- 版本或发布记录是发现更新的证据；是否跟进还需更新内容、契约和补丁影响依据。缺少内容时记录“有版本更新、影响待查”。已发布版本查询不等于任意未发布分支跟踪。
- 后续候选验证绑定本轮取证输入；内容改变后重新检查。不能用旧报告为新输入提供验证结论。

### 差异记录与报告

- 每轮形成相互一致的可读报告和带格式版本的结构化记录，记录检查时间、本项目基线、各来源身份、范围覆盖、差异、建议、证据位置和未决项。
- 差异记录包含稳定标识、对象、两端内容身份、影响、处置意见、理由和复查条件。处置意见区分跟进、保留差异、待分析、不适用；未知来源不能归为不适用。
- 已知决定只适用于其已审阅对象及内容身份。任一相关内容变化后重新提示评审，新增内容不能被宽泛的保留规则静默忽略。
- 比较结果区分首次检查、无新增变化、已知差异、新增变化及旧决定需复查。上次记录缺失或不可读时说明无法完成历史比较，不把所有结果伪装成已知。
- 初始保留差异以现行规格及 ADR 为依据，例如自有 read/edit 与独立 persona/watchdog；它们仍需检查与新宿主内容的兼容性。
- 每轮报告保留独立身份，不改写历史结果。日常本地报告及原始取证留在被忽略的证据目录；需随仓库交付的脱敏结论进入正式验收文档。

### 失败与后续动作

- 部分来源不可用时，继续独立可完成部分，整体标记检查不完整并列出原因。无法确定的字段或影响保持 unknown/GAP，外部依赖阻塞记 BLOCKED；已执行行为不符合契约记 FAIL。
- 旧缓存仅作历史参考，不能证明本次没有更新。缺少必要依据时不能给出可升级结论；建议跟进也不代表候选已验证。
- 检查只写本轮报告和证据，不生成适配代码提交，不改动来源源码、依赖锁定、补丁、日常 profile 或链接，不调用付费模型。
- 用户选定跟进项后才进入适配。候选验证、依赖升级和目标切换复用现有流程与授权规则，按变更范围执行既有门禁；检查报告不代替同意记录或真实交付证据。
- 继续保持 PTC canonical value、read/edit 名称及 schema、Intent gate、seen 有限守卫、CAS、共享物理引擎和既有 cwd/MV/BOM 契约。

## Testing Decisions

用户已确认主要从公开手动检查入口测试完整外部行为。优先复用运维 CLI 的真实子进程测试方式，使用临时源码树和真实文件输出；只在外部发布信息边界提供固定响应或失败夹具。少量规则测试仅补充入口难以诊断的边界，不以内部函数调用次数或实现结构作为验收目标。

既有参考包括 operations CLI 的退出及副作用检查、baseline 的身份缺失处理、upgrade assessment 的来源注入及失败判读、候选验证的输入绑定。候选升级继续沿用原有测试，不另造一套授权及切换测试体系。

| 验收 ID | 外部可观察场景及通过条件 |
|---|---|
| SYNC-01 | 三层路径同时配置时按优先级选中；缺配置、无效路径或断链明确报错，既不扫描也不偷偷回退 |
| SYNC-02 | 普通目录及用户链接解析正确；含本地修改时保留 commit/dirty/摘要；身份缺失显示 unknown，不冒充已发布版本 |
| SYNC-03 | PTC 工具、配置、提示及相关契约变化可定位来源；新增内容不被既有差异规则吞掉；未知行为明确待分析 |
| SYNC-04 | stock read 参数、返回值、截断、大文件及错误变化进入对应差异项；使用与 PTC 相同的 DSH 身份 |
| SYNC-05 | 引擎稳定/预发布候选正确区分，覆盖固定版本至候选的更新依据；同版本不同内容或未知补丁影响不误报兼容 |
| SYNC-06 | 首次及重复运行输出一致的可读报告与结构化记录；新增变化可辨认；已知差异内容改变触发复查；历史记录缺失不伪装为成功比较 |
| SYNC-07 | 发布源失败而 DSH 可读时继续本地检查，整体不完整；反向情形同样处理；缓存不能掩盖来源失败 |
| SYNC-08 | 检查前后来源树、依赖、补丁、profile 和用户链接未被修改；仅生成指定报告及取证产物，无模型请求或升级动作 |
| SYNC-09 | 报告可为选定跟进项提供身份、差异及待办；来源变化令旧输入失效；不能以报告绕过现有候选验证和切换授权 |
| SYNC-10 | Windows 使用真实 DSH 来源及真实引擎发布来源完成一次完整检查，提供逐项意见和待办；重复检查有可核验比较结果 |
| SYNC-11 | Windows/macOS/Linux 的路径、配置与报告逻辑纳入自动化测试；按实际运行平台留证，模拟路径不能冒充其他平台实跑 |

真实来源检查的“完整”要求范围内来源及比较点有明确记录，不要求所有变化都适配或所有行为兼容性均已证明；待分析项仍须显式列出。若必要来源失败，SYNC-10 保留 GAP/BLOCKED，不能用固定响应测试替代。

首版必须完成 Windows 真实来源检查。macOS/Linux 未实跑部分保留 GAP，不阻塞仅在 Windows 范围交付。新增实现运行受影响测试；依赖、preset、运行契约及交付变更按仓库既有完整门禁执行。文档完成不等于上述验收已执行。

## Out of Scope

- 定时自动检查、自动通知、网页后台及自动生成适配提交。
- 自动下载或升级 DSH、自动创建目录链接、扫描整盘选择版本。
- 自动安装引擎、修改官方 DSH 源码、目标切换或宿主重启。
- 无条件追平全部 PTC 功能、全面审计无关宿主模块、首版修完所有能力差距。
- 在本规格中实现大文件流式 read、调整默认编辑策略或替换 Intent gate。
- 真实模型付费评测、重启 S1/S2、证明 Hashline 编辑收益或恢复默认推广。
- 首版强制三平台全部实跑通过；未运行项必须如实保留。
