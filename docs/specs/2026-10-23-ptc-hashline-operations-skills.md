## 继承的已明确要求

- 两份 skill 及资源在本仓库维护，依 bundle 的 scoped provider 交付，不安装到自动全局/项目技能扫描根。
- 升级前先给具体方案并征求真实用户同意；不把创建 skill 的授权当作升级授权。
- 不自动监控、自动外发、修改 gate 或自动重启 DSH。
- 当前阶段仅细化需求与文档，不实施功能。

## 代码核对补充（事实，不是额外用户决策）

- DSH 支持 `disable-model-invocation: true` 与 `user-invocable: true`；前者使模型目录与 skill 工具均不提供加载，真实用户首行 `/<skill-name>` 由宿主显式加载入口注入正文。两份 skill 应使用这套机制落实 D13。
- 子 scope 会继承祖先技能层；同 preset 子 agent 与独立其它 preset 会话不同。工作流权限已按 D5 明确，不把物理可见等同于升级执行授权。
- DSH shell 提供当前 session/profile 管理变量；run_code 的 process.env 不是这些变量的读取入口。
- 实际 preset 投影来自有效 header 初值及后续 selection 事件；不能强制所有合法会话都必须存在 selection 事件，也不能把 family 标记 ptc 当作 ptc-hashline。
- bundle 安装资源路径、维护仓库与升级目标是三种角色；当前开发 link 恰巧重合不代表始终重合。
