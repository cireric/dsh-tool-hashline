# PTC Hashline 默认编辑策略需求规格（SRS）

- 日期：2026-10-24。
- 版本：1.1（复核确认窗口受限与空文件边界）。
- 当前状态（2026-10-26）：工程切片及有界复验已交付；完整 E2/E3/E4 和收益结论未完成。用户已决定[收口为按需维护](../acceptance/2026-10-26-project-closeout.md)，暂停默认推广与评测扩建。下文保留原设计语境；现有 preset 内部契约不变。
- 适用对象：PTC Hashline Mode，preset id 为 `ptc-hashline`。
- 授权边界：本文定稿不授权开发、安装、真实升级、目标 profile 切换、宿主重启或发布。

## 1. 目的、背景和规格关系

当前 PTC Hashline Mode 已关闭 DSH stock edit，挂载同一个上游 `edit` 插件的 Hashline、replace、patch 和 apply_patch 能力。preset 配置为 `mode: auto`，实际按参数分流；文件小、此前 read 返回了 tag，都不会自动使字符串替换变成 Hashline。

实际使用观察显示，该组合能够完成 Hashline 编辑，但也能连续采用 replace 而不使用 Hashline。观察同时存在 Hashline 高采用、内容错误、行号误用、受限窗口和程序构造失败；这些现象不足以证明某种模式普遍更正确或更省成本。replace 是上游 edit 的另一分支，不是重新调用官方 stock edit。

本需求建立：**已有普通文本的局部内容修改默认使用 Hashline；非 Hashline 内容更新只能通过显式受控降级；校验失败先核验和补足依据。** 不以文件行数、修改行数、落点分散、模型习惯或既有开发投入作为降级或推广理由。

### 1.1 两层承诺

1. **执行契约**：受管 `edit` 入口不得静默执行不符合本文放行规则的非 Hashline 内容更新。
2. **行为纪律**：模型不得借 write 覆盖、shell、Python、直接 Node FS 或其他入口规避默认策略。首版不在运行时全面阻断这些旁路，不承诺完整文件系统权限控制。

模型可见指令不能代替执行约束；执行约束也不证明模型永不发错请求、业务修改正确或全部写入均受控。采用率与净收益分别验收。

### 1.2 权威关系和批准增量

本文是默认编辑策略的完整需求正文，不依赖临时草稿、审查记录或本地会话日志。已有读写能力仍以[基础规格](2026-10-22-ptc-hashline-requirements-spec.md)及相关 ADR 为准。

本文对基础规格的批准增量仅为：目标 preset 增加默认编辑策略与入口约束；允许必要的降级输入契约；局部协调 persona 的失败恢复、auto 模式说明、编辑策略指令及 read canonical nextAction 指引，并更新对应资源基线。原有无 tag 替换/补丁能力改为按本文受控使用。

Intent 门判据、watchdog 行为、hashline 算法和有限 seen 语义不变。本文不把基础规格的“首版 persona 正文不变”扩大为禁止本次已批准的局部演进，也不借本次演进取消资源摘要检查。

## 2. 术语与运行基线

“必须/不得”是验收要求；“宜”是可说明理由的推荐。未特别说明时，“内容更新”指对已有非空普通文本文件的内容修改，包括用创建形状覆盖已有内容；是否属于更新按实际状态与效果判定。

| 术语 | 本文定义 |
|---|---|
| 受管 edit | 在目标 preset 范围内注册并应用本策略的 `edit` 调用，包含主代理、同 preset 子代理和 PTC 内层派发 |
| 空文件 | 按[术语表](../../GLOSSARY.md)的归一化文本为空判定；包含单 BOM 文件，例外仍受 FR-01 的保真条件约束 |
| tag | 整篇归一化内容的 4 位大写十六进制摘要；不因 read 分页变为窗口摘要，不是强版本锁 |
| seen 行 | 引擎按会话记录的完整展示行号；read 只新增完整返回行，零完整行使用 `[0]`，合并交给引擎 |
| observed | 宿主文件策略的观察事实，支撑后续写入判定；与 seen 的归属和路径键不同 |
| show path | read canonical value 返回的规范路径；模型可用于后续 edit |
| store key | 由有效 workingDirectory 与作者路径解析得到的快照键；read/edit 必须同源 |
| 降级 | 对本应受内容更新策略约束的目标，使用 replace、patch 或 apply_patch；必须声明本文支持的原因和依据 |
| 例外操作 | 真正创建、空文件填充、纯删除/移动，以及适用的外部专用工具任务；不等于任意非 Hashline 更新许可 |
| 修改目标 | 预先定义、具有独立预期结果的业务目标；方式选择按“文件＋修改目标”分项记录 |
| 候选修改尝试 | 为一个目标构造的一组完整候选修改，可含多个工具调用；与工具调用、PTC 程序及模型往返不同 |
| unknown | 证据不足，不能确认事实；不能按成功、未发生或零成本处理 |

### 2.1 保持的现有契约

- 验证基线为 DSH `0.2.1-rc.2`、hashline/tool-edit `0.2.1-alpha.4` 加本地精确补丁；升级时核验实际解析路径和补丁，不能仅比较版本号。
- read/edit 使用有效 workingDirectory，并共享同一物理 hashline 实例。相对路径、show path、别名和快照键继续遵循 ADR-0003。
- read 默认窗口为 2000 行、每行 2000 字符、51200 字节，快照门槛为归一化 UTF-8 文本 4 MiB。read 仍读取全文；分页不代表降低磁盘读取量。
- read canonical value 包含 path、tag、tagged、offset、lines、totalLines、nextAction。edit canonical 输出是字符串，不提供 editResult.tag/lines。
- PTC 程序消费 canonical value；工具完整返回不等于模型已理解全部内容。替换渲染 content 不能代替规范接口。
- seen 有 recovery、错误回显、跨会话、淘汰、REM/block 和 mismatch 等既有边界，不是全部未见内容的权限边界。新策略不增加“所有受影响行必须 seen”的引擎保证。
- Hashline 不证明业务意图、语法或 AST 边界正确。replace 仍有匹配、歧义处理及宿主条件写入，不是无校验路径。
- MV 保持两端目录约束、目标 createIfAbsent、不覆盖、部分成功报告和磁盘先于快照的提交顺序。多节编辑及移动没有全局事务或自动回滚保证。
- BOM 保真仅沿用 ADR-0005 已确认的 Local provider、零/单 BOM Hashline 路径；连续 BOM 拒绝，保证不扩展到替换/补丁或其他后端。

## 3. 首版范围与非目标

### 3.1 包含

- 目标 preset 的一致模型指令、默认编辑路径、失败恢复和例外纪律。
- `edit` 入口的执行约束、封闭的降级原因集合、依据核验和逐调用有效性检查。
- 保留 auto 分流及替代能力；必要的已声明降级输入字段同步进入参数校验、SDK、文档和测试。
- 主代理、同 preset 子代理、PTC 派发、其他 preset 隔离及相关错误路径的验证。
- 最小可追溯事实、本地脱敏评测、真实模型重复运行，分开给出工程和推广结论。

### 3.2 不包含

- 全文件系统写入拦截、统一写入代理、shell/Node FS 全面审计或新增沙箱后端。
- 自动把 old_string 转成行号，或复制/fork 上游源码、DSH，重写解析器、快照、recovery 和 seen。
- 修改 read/edit 名称、read 输入输出字段及其 schema、edit canonical 输出及其 schema、默认窗口或快照门槛；read nextAction 指引文案按 FR-07 协调。
- 完整结构化 diff 输出协议、窗口独立 tag、AST 所属块提示、任意 --check 命令执行框架。
- 常驻遥测、每次编辑的审批/说明模板、运维 skills 工作流变更、自动安装切换或重启发布。

具体模块、输入字段名称、证据存储和错误标识由实施计划设计；本文的原因集合、放行条件、信任边界和失败规则不得留给实现自行改变。

## 4. 功能需求

### FR-01 默认路径、操作分类与适用范围

已有普通文本的局部内容修改，能够在编辑会话建立 tag 和目标依据、目标锚点及必要上下文完整且操作可由现有 Hashline 能力表达时，必须默认使用 Hashline。应读而未读不构成“没有 tag”的例外。

按实际状态和效果分类，不只看 op、文件名或作者自称的操作类型：

| 操作 | 首版处理 |
|---|---|
| 真正新建不存在的文件 | 沿用现有创建能力及宿主条件，不要求为初始内容构造 tag |
| 填充归一化文本为空的文件 | 按创建类例外处理，保留现有观察/写入策略；零字节文件与仅含单个前导 BOM 的文件均适用，不把仅含空白或连续 BOM 的文件当作空文件 |
| 替换已有非空文本，包括以 create 形状覆盖 | 内容更新，默认 Hashline；非 Hashline 须满足 FR-03/06 |
| 纯删除、纯移动/重命名 | 沿用现有能力和目录、权限、不覆盖等契约，不纳入局部内容编辑采用率 |
| 移动同时修改内容 | 内容更新部分仍适用默认策略，移动部分保持原契约 |
| 一次请求含多文件/操作 | 逐项分类和核验；创建或一个受限目标不能放行其余普通更新 |

真正新建的预判不授权覆盖检查后出现的已有文件；继续遵守宿主原有条件写入和冲突拒绝。本文不新增创建、删除或移动能力。

空文件分类沿用基础规格的归一化文本为空口径，不等于原始字节数为零。单 BOM 文件填充仍须满足任务所需的 BOM 保真，无法保证则停止；分类本身不扩展 write、replace 或补丁路径的保真保证。连续 BOM 不因读取后呈现为空而获得例外。

同一 edit 请求内删除后重建已有内容等组合，仍按请求整体的实际效果分类，不能逐项拆成“纯删除＋真正新建”来豁免内容更新。跨调用拆分以规避策略属于 §1.1 的行为纪律，不据此声称首版具备跨调用的全面阻断能力。

整文件重写必须有任务必要性，不作为局部修改规避入口。多落点、大区间、小文件、单字符修改和模型熟悉替换均不自动形成例外；不设置按行数或改动占比自动降级的阈值。

需要模型理解新代码、选择位置或设计修改时，先向模型返回足够上下文。用户已明确且程序可验证前提的机械修改，允许同程序 read→验证→edit，不强制增加模型往返。

### FR-02 按目标建立和更新编辑依据

- 使用 read canonical value 的 path、tag、行号构造调用，不猜卡片内容、不伪造 tag。按需读取目标窗口；普通小文件一次完整返回不属于违规全文读取。
- 目标未覆盖先补读；先判断目标和必要上下文，不因无关行截断降级整个文件。nextAction 是补救指引，不是无条件降级许可。
- 零行窗口、截断后缀和省略标记不作为完整锚点或 old_string。分页可补足则补读，同配置无法揭示所需内容时停止无效循环；不擅自改配置或重挂载。
- 同文件多个独立修改宜合并到一个 header 下，按本次编辑前的行号表达多个操作；不为减少调用扩大替换范围或重建无关内容。
- 连续编辑只复用实际结果可确认的新 tag、完整内容及行号。新 header 不证明全文行号已知；结果不足则补读，不依赖不存在的结构化 edit 字段。
- 不混用新 tag 与旧内容的行号；换目标文件本身不意味着另一文件 tag 必然失效。成功 recovery 不要求重复执行已经完成的修改。
- 同 preset 子代理必须在自身会话建立 read/seen，不直接借用父会话或其他子代理快照依据。用户指令来源的委派追溯按 FR-03 单独处理。

### FR-03 封闭的降级原因与信任边界

首版只允许下表三类降级原因。类别名称表达业务语义，具体输入值由接口设计映射；不得新增任意文本理由的通用放行口。原因有效只表示满足模式例外，不取消内容依据、保真、宿主策略或用户权限要求。

| 原因类别 | 必须满足的条件 | 必须拒绝或先补救的情况 |
|---|---|---|
| 快照门槛限制 | 目标归一化文本达到当前生效的 snapshotMaxBytes，无法由 read mint；执行层核验实际事实 | 仅凭行数、原始文件大小或模型声明；当前目标仍可按门槛 mint；未读便声称无 tag |
| 目标窗口确实受限 | 目标编辑所需内容被当前 read 列/字节上限限制，调整 offset/limit 仍不能补足；执行层核验目标与限制关联 | 仅窗口未覆盖、无关行截断、当前 read 已提供 Hashline 可用的完整目标锚点及必要上下文，或重复相同 read 没有新依据 |
| 用户明确覆盖默认 | 可引用真实用户请求，声明本次目标、方式和范围；来源与引用范围由系统核验，语义一致性由模型与验收负责 | 只有模型声称“用户要求”、引用非用户内容、来源不存在/无法确认、声明范围不覆盖本次目标或方式 |

未列能力限制不自动降级，应报告具体限制与缺失依据。无 session 不属于首版降级原因：命中受管策略却缺少必要会话上下文时拒绝；明确不属于目标 preset 的调用保持原行为，不能把上下文缺失当作自动退出策略的证明。

所有内容更新降级还必须满足：通过可用且获准的方式取得唯一定位和修改所需的完整内容；替代路径满足任务所需的文本/字节保真；保留 observed、版本、路径、权限与沙箱检查。截断后缀不是文件原文；不能建立充分依据就停止并报告缺口。

目标窗口受限与替代内容充分是两个独立条件。例如，当前 read 无法完整返回目标长行，经获准渠道取得完整原文后，可在窗口限制及其会话、目标和配置依据仍有效时声明该原因降级。替代渠道取得原文不自动消除 read 的窗口限制，也不自动取得额外读取或写入权限；可由正常补读获得 Hashline 可用依据时仍应补读。

BOM 或其他特殊文件的保真未知，不自动构成降级许可；连续 BOM 的 Hashline 拒绝也不能仅凭“不支持”换入口写入。必要内容是否足够理解、任务需要何种保真，属于明确的模型纪律与验收责任，不宣称入口能自动证明全部语义。

用户覆盖不要求新增逐次审批。系统核验真实来源和声明范围，不承诺自动理解任意自然语言；“消息真实”不等于“任意解释都获授权”。模型必须忠实解释原文，错误归因在评测/审查中记为偏离，不因来源检查通过而免责。

子代理可追溯本任务父会话的原始用户要求；系统核验来源及委派关联，模型/验收核对是否确实覆盖当前任务。转述、工具输出或子代理自身消息不成为新的人类授权，不允许扩大原请求范围；此引用不转移父会话 read/seen。

formatter、生成器及专用机械修改工具仅在任务本身需要、项目工作流要求或文件明确由它维护时作为外部专用工具例外，核验实际结果。工具存在不等于适用，临时覆写脚本不能自封专用工具；若仍通过通用 edit 更新内容，须遵守上述三类原因，不新增第四类解锁理由。

### FR-04 失败计数、停止与恢复

- mismatch、未见锚点、明确快照依据丢失时，先核验和补足依据，再构造修改；拒绝本身不提供降级资格。
- 参数/语法错误修正调用；权限、策略、取消、磁盘错误按原原因处理，不通过换入口绕过。上游 recovery 成功不重定义为一律冲突拒绝。
- no-op 先区分目标已满足与定位/参数错误；已满足则核验后结束，不为制造写入而扩大修改。同一错误且依据无变化时不得原样重试。
- 失败计数针对同一修改目标、需要模型修正或恢复的一次失败尝试；同一次尝试在外层/内层出现多条错误不重复计数，工具内部自动重试不另计。正常存在性探测和经核验已满足的 no-op 不计失败。
- 同一目标累计连续三次失败尝试后停止编辑，保留现场、记录尝试并请求独立复核或必要信息。只读成功不清零，目标经核验完成后结束计数；独立目标分别计数，不能改名来重置同一问题。
- 权限拒绝、反复漂移、状态不明或部分成功可更早停止，不必凑满三次。该计数是模型恢复纪律，不新增运行时计数门，也不改变引擎已有 no-op 守卫。
- persona 中无条件 REVERT 必须局部协调为先停止、保留现场和核验。回退前辨明本次已落地内容、用户已有改动及实际状态，不擅自撤销用户工作。
- 工具、批次或 PTC 程序失败不证明此前副作用回滚。部分成功先检查磁盘及涉及路径，再决定剩余操作，不盲目重放 edit、MV、REM 或整段程序。

### FR-05 结果核验与用户说明

一组相关修改完成后，以实际 diff 或足够的目标内容核验预期，并执行与风险相称的类型、语法或测试检查。后续操作依赖不确定状态时提前核验，不重复已有充分证据，不要求每笔编辑都读全文或跑完整门禁。

Hashline 压缩预览不等于完整 diff，replace 成功文本也不是业务正确证明。分别判断工具接受、实际变更、业务正确；PTC 外层结果、内层错误和磁盘状态分开取证。失败须区分业务实现、模型生成内容/参数、程序构造、环境和证据不足。

普通成功不额外输出 tag 教程或模式报告。降级、用户覆盖、专用工具例外、部分成功或无法继续时，同一任务汇总一次简短具体说明；评测逐项留证。不要求日常新建独立日志或重复用户确认。

### FR-06 edit 入口、依据生命周期与异常行为

本节“本次请求”指单次 `tools.edit` 调用，包括其中的多文件、多操作；预检查范围不扩大到整个 `run_code` 程序，也不为程序内多次调用提供事务保证。

1. 先确定受管范围和必要上下文，校验参数，再按实际模式和操作效果分类、核验例外及降级，最后交给原工具执行。不得以模型声明模式代替真实分流。
2. `old_string/new_string/replace_all`、`edits`、`input` 三类编辑载荷必须互斥；多类并存报参数错误且不执行，不能利用上游字段优先级绕过策略。各类仍须满足原有必填和语义校验。
3. 对已有非空文本更新，未声明有效降级的 replace/patch/apply_patch 请求，在产生本次请求的磁盘修改前拒绝；不自动把 old_string 转换为 Hashline。
4. 降级原因和依据须有已声明输入契约，进入实际参数校验、生成 SDK、文档和测试。Hashline 正常调用不要求附降级说明；必要字段仅服务于策略，不重设计全部工具 API。
5. 每次 edit 独立核验，不提供可复用解锁令牌、固定分钟数有效期或整个会话永久解锁。此前依据可用于核验，但不能免除本次事实与范围检查，也不意味着每次必须重读全文。
6. 依据关联当前编辑会话、有效目标及其事实。文件状态、有效工作目录、解析目标或相关配置变化后，必须重新核验受影响条件；别名使用现有 read/edit 路径语义，不自行创造另一套快照键。
7. 用户来源可沿合法委派关联追溯父会话；文件读取/窗口事实不能挪用其他编辑会话。用户请求的适用范围也必须逐调用核对，不能借一次来源检查永久解锁。
8. 内部重试不能沿用已失效的降级条件；后续执行或内部重试时条件变化须重新核验，无法确认则停止相应非 Hashline 更新。此前已有落盘内容须报告为部分完成，无法确认的状态保留 unknown，不宣称整次请求无修改。不得以策略检查替代或放松原有条件写入/CAS。
9. 混合请求的所有受约束更新必须在本次请求开始写入前完成策略核验；任一不合格则整次请求不开始写入。放行后仍可能按上游顺序部分提交，不承诺事务或回滚。
10. 缺失、虚构、矛盾、失效、范围不符或无法核验的依据不得放行。策略组件异常或核验不可完成时，受管非 Hashline 更新拒绝并返回具体缺口；仍可正常执行的 Hashline 路径不因此被无条件禁用。
11. 必要会话上下文缺失时，受管请求按 FR-03 拒绝；不得借第 10 项绕过上下文要求。拒绝不伪装成功、不吞掉宿主已有拒绝、不新设逐次审批。其他 preset 的原行为不变。

该执行约束仅控制受管 edit。write 覆盖、shell 和直接 Node FS 的规避属于模型偏离，不得报告成已被该入口阻断；不为首版新增全写入代理。

### FR-07 指令一致性、最小记录与接口兼容

模型实际收到的组合提示词、工具描述和 PTC SDK 必须一致说明：默认 Hashline、受控替代、真实参数分流和失败先核验。不得保留与 auto 冲突的“单会话固定形状”承诺。仅增加文件或改配置值不算策略已加载。

一致性验收还须覆盖 read canonical nextAction 及其渲染指引：无必要会话上下文时不得推荐受管降级；快照或窗口受限时说明受控条件，不暗示直接替换许可或擅自改配置、重挂载。文案协调仅作用于目标 preset，保留其他 preset 原行为及 read 原有字段、schema、窗口和 mint 规则。

主代理及同 preset 子代理都须受到策略约束；子代理覆盖 persona 后策略仍可见。不得改变其他 preset，或顺带改变 Intent 门判据和 watchdog 行为。

最小记录必须能关联一次请求及其内层调用，并保留下列事实；可复用已有日志和保持 string schema 的回执，不新增常驻遥测：

| 事实 | 记录规则 |
|---|---|
| 调用关联 | 可追溯当前会话、调用；PTC 内层还可关联外层调用；不重复计数 start/settle |
| 目标与方式 | 声明/解析目标、请求载荷类别、实际分流；未派发时明确记未执行，不虚构实际执行模式 |
| 降级 | 原因类别、依据引用、核验结论和拒绝缺口；不只记录自由文本自述 |
| 结果 | 区分拒绝、接受并完成、未变更、失败、部分完成和 unknown；接受不自动等于业务正确 |
| 证据边界 | 不能确认磁盘状态或实际结果时保留 unknown，不能只凭程序失败推断无副作用 |

优先记录必要标识和引用，不额外复制完整用户消息、文件正文、环境或凭据。评测导出应脱敏，不能为了证明来源而扩散原始内容。

保持原有 string 输出及 tag/header 消费方式；新增说明不能破坏连续编辑获取新 tag 的既有契约。仅写入 meta 不等于 PTC 程序获得新字段。不新增完整结构化 diff，也不通过本需求顺带修改解析、自动修复、no-op 或 PTC 错误语义。

## 7. 推广评估与退出条件

### 7.1 工程和推广分开

工程验收证明加载、执行约束、例外和兼容性；推广评估证明真实模型是否采用、任务是否正确及总成本是否可接受。允许“工程通过、推广证据不足”，不得合并为全面通过。

执行前必须发布并冻结评测方案：实际依赖及补丁、模型与参数、工具配置、任务初始内容、独立预期结果、样本与重复安排、执行顺序、预算、正确性和成本通过条件。具体模型、次数及阈值是评测执行前的必需交付项，不在本文编造，也不能看完结果再改分母或条件。

### 7.2 计数口径

- 业务任务按独立预期目标定义，失败重试不新增任务；方式选择按“文件＋修改目标”分项。
- 全部目标 = 已知适用 + 有依据的例外 + 无需修改 + 适用性 unknown，四类互斥。适用性由预置条件和独立检查确定，应读而未读不能排为例外。
- 已知适用采用率 = 首次编辑尝试选择 Hashline 的已知适用目标数 / 已知适用目标总数。非 Hashline、未尝试和首次方式 unknown 均单列且不移出该分母；分母为零记不适用，适用性 unknown 同时报数量。
- 全程另外记录 Hashline、非 Hashline、混合、未尝试及方式 unknown，不能以第一笔 Hashline 代表全程遵从。不得把已知适用比例推广为全部目标的精确比例。
- 首次正确率以首次完整候选修改尝试为单位：允许其中包含预先安排的一组工具调用，按相同完整目标检验。因失败或发现错误而修正既定候选算重试，不得事后把修复并入首次批次；批次边界在评测方案中预先定义，不新增日常用户模板。
- 首次尝试正确、最终正确、工具接受和实际变更分别报告。预期冲突组单列，独立预期可要求正确拒绝或报告，不把守卫拒绝混同于错误写入。
- 正常首读不是返工；按需补读、失败后的重复读取、内容错误修正分别记录。区分业务实现、模型参数/程序、预期守卫、环境和证据不足。
- 成本涵盖总输入/输出 token、耗时、模型请求、run_code、内层工具、读取及核验。一个程序的多次 edit 不是多轮模型往返；内部重试能测则另记，不能测记 unknown。
- 记录入口拒绝及例外负担，不把强制后的高采用率当作收益，也不因程序异常推断没有此前副作用。

### 7.3 对照任务和推广判定

比较当前 auto 与新增策略，可另设仅纠正指令组区分提示和执行约束影响。使用相同初始文件和任务、可比环境及独立会话，按冻结安排重复；不筛掉失败样本。

任务至少含：小文件单点、重复片段、同/跨文件多落点、连续编辑改变行数、read 后外部变动、无关长行和目标长行截断、受限降级、大范围内容重建、目标已满足。新建、用户覆盖与专用工具例外单列。用独立预期和实际 diff 判定正确，不以工具成功或模式名称判定。

历史使用观察不是已完成 A/B；样本少、指标缺失或环境不可比时只报告观察，不作统计推广。只有工程验收成立、正确性和总成本满足冻结条件，且有可复现的定位、返工或输入成本收益时，才建议推广。

若只有采用率提高，成本持续增加且无对应收益，应建议缩小默认范围或停止通用优先；既有投入不构成继续推广的理由。推广结论不替代目标切换的当次用户授权。

## 8. 实施与交付约束

实施计划必须落实：策略的 scoped 注册、入口位置、输入契约、三类原因的事实核验、用户来源引用、混合请求预检查、依据失效/内部重试、最小记录及验收映射。模块划分和字段命名属于设计任务，不再重开是否设置入口约束、是否允许输入扩展的范围决策。

本需求不授权自动实施。后续获得开发授权后仍须保留用户已有改动；不热改运行中宿主依赖，不自动重启、发布或切换 profile。不得把打包安装、模拟候选、注入 runner 或一次性 profile 的验收说成真实上游升级。

正式需求只维护本文一份正文。已有能力和历史执行结果从当前验收索引查证；本需求的实现及验收记录另行交付，本文“已确认”不等于“已实现/已验收”。
