## 1. 结论摘要

1. **质量:两臂三任务全绿,「改错目标」探测器零触发。** T1 的 CLASSIC 主色断言是专门的静默错误探针
   (误改第一个条目会当场红),两臂都通过;盲判意见见 §8。
2. **成本方向与第一轮相反。** 本轮 A 2.9 M vs B 3.4 M(**A 便宜约 15%**),墙钟 362.6 vs 383.0 s、
   步数 39 vs 49、edit 调用 8 vs 41 —— A 在四个成本维度上都不贵。第一轮是 A 贵 1.93×。
   **两轮方向翻转,直接支持第一轮报告的归因:成本差是 preset 组合与行为噪声,不是编辑机制的固有成本。**
3. **编辑形态差异稳定复现且符合预测,但依旧没有兑换成收益。** A:8 次 edit 装 39 个操作(5/8 多 hunk、
   1 次 `CUT` 搬 60 行、2 次跨文件调用);B:41 次 edit(old_string 中位 3 行/75 字符,最长 61 行/1630 字符,
   26/41 多行)+ 8 次 write。T3 搬移任务上 A 一发 `CUT`,B 是 61 行 old_string 整块双写 ——
   「搬移场景」的形态差坐实,但两臂都零失败、墙钟相当,形态差未转化为质量或成本差。
4. **歧义任务改变了行为,但仍未产生失败。** 面对三个逐字相同的表条目,两臂都放弃了逐条目外科手术:
   A 用一次 `PUT 3.=79:` 整表替换(77 行跨度),B 直接 `write` 重写整个 themes.c(+themes.h)。
   **歧义税以 payload/策略成本支付,不以失败率支付。** 判定表「歧义未被检验到」一行仍然成立,
   但要加注:区分度在行为形态上出现了。
5. **A 的失败从 3 次降到 0 次**(第一轮:2 次 hashline 礼仪 + 1 次意图门)——「固定礼仪税随熟练度衰减」
   得到支持。
6. **B 的一次 checker 红是 checker 误判,不是质量缺陷**(§7)。它暴露了 v2 设计时已记录的口径模糊 #3,
   checker 已修,修正前后结论都留档。
7. **协议合规差异:** A 按要求逐任务输出 `[T1 DONE]`/`[T2 DONE]`;B 只输出了 `[ALL DONE]`
   (其推理里自称已输出 T1/T2 标记,实际文本块中不存在)。B 的逐任务墙钟因此只能按活动窗口估计。
8. **盲判(揭示后):两臂均无静默错误;唯一质量差异是完成广度** —— A 的 T2 留下 toast 文案范围缺口,
   B 做得更彻底;独立评审者不知身份,判定 **B 更可信**。这是本轮唯一的质量向差异,且恰好落在
   checker 字面覆盖不到的地方(§8)。

## 2. 归因边界

与第一轮相同,未对齐 preset 差异面(系统提示、意图门 `mode=enforce` 仅 A 有、工具白名单)。
**所有结论只能写成「preset 组合差异」。** 本轮补充:两轮成本方向翻转本身就是证据 ——
若成本差是 hashline 机制固有,方向不应随运行翻转。

## 6. 歧义任务的行为观察(T1)

三个逐字相同的条目按设计应让「精确匹配」撞车。实际发生的是**策略规避**:

- 两臂都识别出表的整块性质,选择整块重写而不是逐条目编辑 —— 歧义没有变成失败,变成了 payload 成本
  (A:77 行替换体;B:84 行文件全文 + 头文件全文)。
- **CLASSIC 的占位值两臂都逐值保留**(checker 主色断言 + 盲判复核)——本想做「改错目标」探测器的
  断言零触发,任务包的最强质量判据这次没有取到阳性样本。
- 对结论的修正:「精确文本匹配的唯一性成本≈0」在两轮里都没被否证,但 round-2 显示它的对手不是失败,
  而是「被迫整体重写」的策略成本 —— 这个成本在 replace 与 hashline 上都出现,不构成两者的差异。

## 7. 失败明细

两臂 edit/write **0 失败**(含 A 的意图门:0 拒绝;第一轮 A 有 3 次)。

唯一「红」是 §3 记录的 checker 误判事件:B t3 隐藏探针链接失败(`undefined reference to g_text`),
根因是 B 把 toast/clear_name 文案也集中进了字符串表(对 T2「界面文案集中」的字面理解更彻底),
而探针链接集假设 game.c 自封闭。**这不是静默改错目标,也不是意图未达成 —— 是验收器覆盖面缺陷。**
该缺陷对两臂对称(任何把文案集中到 game.c 依赖模块的合法实现都会中招),已修复并留档。

## 9. 协议合规与混杂记录

1. **标记合规:** A 输出了 `[T1 DONE]`/`[T2 DONE]`/`[T3 DONE]`+`[ALL DONE]`;B 仅 `[ALL DONE]`,
   其推理自称「已输出 T1/T2 标记」与事实不符。B 的逐任务墙钟(表 §4)按工具调用活动窗口切分,
   与 A 的「提示词到宣告完成」口径略有差别(约 ±10 s 量级)。
2. **提示词保真:** 见页首;两臂逐字符一致。
3. **串行协议未执行(偏差):** 两臂实际并行运行 —— A turn 13:00:28→13:06:30,B 13:01:39→13:08:02,
   重叠约 291 s。墙钟与 make/gcc 构建耗时受同机争用影响,两臂墙钟差(362.6 vs 383.0 s)只能当参考量;
   token 总量与调用计数不受影响。

4. **临时文件:** 两臂都在 `.probes/` 下写了验证脚本(A `theme-check/`、B `tetris-themes/`),
   未越界改树外源码;B 的 shell 调用多为构建与抓帧脚本,无 shell 直改源码绕过。
5. **意图门:** 仅 A 有(`mode=enforce`),本轮 0 拒绝;其自我调度开销仍属 preset。
6. token 总量由实验者提供,日志无 usage 字段,无法复算与拆分。

## 10. 两轮合并视图

| 维度 | round-1(逐条提示词) | round-2(连续提示词) | 合并结论 |
|---|---|---|---|
| token | A 7.9 M / B 4.1 M(A 贵 1.93×) | A 2.9 M / B 3.4 M(A 便宜 0.85×) | **方向翻转:成本差不可归因给机制,单轮成本结论不可信** |
| 失败 | A 3(礼仪+门禁)/ B 0 | A 0 / B 0 | A 的固定税随熟练度衰减;歧义仍未逼出失败 |

| 质量 | 两臂全绿 | 两臂全绿(修 checker 后);盲判见 B 完成广度更优 | 「改错目标」两轮均零触发;round-2 出现完成广度差异(B>A),方向利好 replace 臂 |
| 歧义命题 | 未检验(无歧义源) | 有歧义源,但被整体重写策略规避 | 「唯一性成本」的真实形态是 payload/策略成本,两模式都要付 |

**决策含义:** 在 12k 行 C 项目、中等规模任务、单会话形态下,PTC mode(精确替换)已足够完成任务;
hashline 的形态能力(批量、多 hunk、CUT/MV、跨文件调用)真实存在且能把 edit 调用压缩约 5 倍,
但两轮均未观察到它兑换成质量优势或稳定成本优势;round-2 中 replace 臂反而在成本(token、墙钟、步数)
与完成广度(盲判)两个方向同时占优。**当前证据不支持为 hashline 付额外复杂度;但也不足以证明它无价值 ——
三个预测场景里只有「搬移」取得了形态级证据,真正的高价值场景(长重复块歧义、15+ hunk 散布、超大文件)
仍未被任务包触及。**

## 11. 本报告不能说明什么

- n=1/轮;两轮的运行条件还不同(提示词形态、任务包、checker 版本),只能作趋势对照,不能合并统计。
- 归因止于 preset 组合;hashline 单独的作用仍未被隔离。
- 成本数据 token 为实验者提供,不可复算;B 的分段口径与 A 不完全一致。
- T1 歧义被策略规避,「精确匹配在歧义下脆弱」仍未被正面检验;要检验需要禁止整体重写
  (如限定改动行数),但那会引入新的协议约束偏差。
- 盲判为单评审者、best-effort 盲(工作区里存在映射文件,已要求评审者不读)。
